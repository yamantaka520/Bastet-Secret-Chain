🐈 The first tagged build of Bastet Secret Chain — a local-first, self-hosted
vault for credentials, built so an **AI agent can fetch exactly the secret it
needs, at the moment it needs it**, without that secret ever living in a URL, a
prompt, or a shell history.

Humans put credentials in through a Web UI. Agents take them out through an
authenticated reference, one at a time, and every retrieval is appended to a
hash-chained ledger.

## What is in it

- **One binary.** `bsc` is the CLI, the daemon, the web server, and the React UI,
  with SQLite (WAL) as the store. No runtime, no database server, no container.
- **Envelope encryption.** Argon2id → key-encryption key, per-version data keys,
  XChaCha20-Poly1305, encrypted item names with a blind search index.
- **Scoped agent tokens.** Expiring, revocable, quota'd and rate-limited; the
  value is shown exactly once.
- **A reference URL grants nothing.** That is the project's defining constraint.
- **MCP server** with six read-only tools — the intended way for an agent to
  reach the vault, so the value never passes through a shell and the token never
  appears in a command the agent writes.
- **Use without seeing.** Bind an item to a URL pattern and a header, and the
  daemon makes the call with the credential injected; the agent sees only the
  service's answer.
- **Approval without fatigue.** Task sessions, trust-on-first-use per
  token × item, pre-authorization, tiered defaults, and a reminder ladder
  (0 s → 20 s → external channel at 60 s) ending in a definite auto-deny.
  The optional Telegram channel is outbound-only and never carries a secret.
- **Hash-chained audit ledger**, with anchors kept outside the vault so a
  truncated tail is detectable, and a break-glass export under a separate
  passphrase.
- **Runs anywhere you do.** `bsc service install` for launchd, systemd user
  units and Task Scheduler; a system unit, unattended unseal and an anchor timer
  for servers behind a reverse proxy.

127 tests pass on macOS, Windows and Linux.

## Install

```sh
sh scripts/install.sh v0.1.0            # macOS, Linux
.\scripts\install.ps1 -Version v0.1.0   # Windows
```

Both verify the archive against `SHA256SUMS` below. Read the scripts before
running them. To check the build's provenance as well:

```sh
gh attestation verify bsc-0.1.0-<target>.tar.gz --repo yamantaka520/Bastet-Secret-Chain
```

Then:

```sh
bsc init && bsc service install && bsc doctor
```

## What this release is not

- **The binaries are not signed with a project key.** The checksums and the
  build-provenance attestation are what you can verify today; signing is the
  next milestone.
- **No external security review has been done.** The design and its residual
  risks are written down in `docs/THREAT_MODEL.md`; read it before trusting this
  with production credentials.
- Parsers have not been fuzzed, and a restore-from-backup drill has not been
  run and recorded. Both are M7.
- Unattended unseal means root on that host can unseal the vault. That trade is
  stated in the installation manual, and the feature is off by default.

Milestone-by-milestone evidence, including what each one deliberately did not
do, is in `docs/M1_VALIDATION.md` … `docs/M6_VALIDATION.md`.

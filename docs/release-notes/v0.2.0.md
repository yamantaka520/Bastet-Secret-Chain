🐈 M7, the hardening pass — and the Web UI now speaks five languages.

## Security

- **Fixed: a break-glass bundle could dictate how much memory the reader
  spends.** A `.bscx` file carries its own Argon2 parameters, because the
  reader has to know how to derive the key. `open_bundle` checked only that
  they were non-zero: a bundle claiming `m_cost_kib = 0xFFFFFFFF` made
  `bsc import` attempt a four-terabyte allocation before the authentication tag
  could reject the file. Parameters read from any file are now bounded at
  1 GiB / 16 passes / 16 lanes. This matters because a break-glass bundle is
  designed to be handed over by somebody else. Found while writing the fuzz
  targets, before any fuzzer ran.
- **Fixed: a per-call memory leak** in the bundle AAD construction.
- **Releases are signed.** The release workflow signs `SHA256SUMS` with
  Sigstore keyless signing and verifies it before drafting:

  ```sh
  cosign verify-blob --bundle SHA256SUMS.cosign.bundle \
    --certificate-identity-regexp "^https://github.com/yamantaka520/Bastet-Secret-Chain/.github/workflows/release.yml@refs/tags/" \
    --certificate-oidc-issuer https://token.actions.githubusercontent.com SHA256SUMS
  ```

  It proves the artifacts came out of this repository's release workflow at a
  tag. It does **not** prove a maintainer approved that tag: there is no
  project signing key, and anyone who can push a tag can produce a valid
  signature. `SECURITY.md` says so too.
- **Parsers are fuzzed.** Four `cargo-fuzz` targets over everything that reads
  bytes this program did not write — sealed ciphertext, bundle, anchor lines,
  export JSON — on every relevant push and for longer weekly.
- **Dependencies have a policy.** `deny.toml`: licences, bans and sources on
  every push, RustSec advisories daily.

## Added

- **The Web UI in five languages** — 繁體中文, 简体中文, English, 日本語, 한국어.
  The picker is in the sidebar and on the unseal screen, because before
  unsealing there is no sidebar and someone who cannot read the current
  language needs a way out. A first visit follows the browser.
- **A restore drill that actually runs** (`crates/bsc/tests/restore_drill.rs`):
  copy the vault file, delete the original, restore, verify every value and the
  ledger; then the successor's path — `bsc export` under a second passphrase,
  `bsc import` into a different vault with a different passphrase. Including
  the failures: a backup is useless without the passphrase, and a wrong export
  passphrase is refused three ways.
- **`docs/EXTERNAL_REVIEW.md`** — six claims a reviewer should try to break,
  each mapped to code and tests, and the eight weaknesses we already know
  about. It is written to be used, and it has not been used yet.

136 tests on macOS, Windows and Linux.

## What this release is still not

**No external security review has been done.** Everything above is
self-assessed. `docs/THREAT_MODEL.md` and `docs/EXTERNAL_REVIEW.md` say where
the soft ground is; read them before trusting this with production
credentials.

# 使用手册

**适用版本：**Bastet Secret Chain 0.1.0
**语言：** [繁體中文](../zh-Hant/guide.md) · **简体中文** · [English](../en/guide.md) · [日本語](../ja/guide.md) · [한국어](../ko/guide.md)
**延伸阅读：**[安装手册](install.md) · [Agent 接入手册](agents.md)

这份手册写给保险库的拥有者：怎么把凭据放进去、决定哪个 Agent 能读什么、怎么响应审批请求，以及事后怎么证明谁读了什么。

---

## 1. 概念一次讲完

| 术语 | 意思 |
| --- | --- |
| **保险库** | 一个加密文件。**上锁**代表密钥不在内存里，任何内容都读不到——包括你自己。**解封**代表有人输入过口令。 |
| **条目** | 一份凭据：一组登录账号密码、一把 API Key、一份服务账户 JSON、一把 SSH 密钥。有路径、名称、类型、标签。 |
| **版本** | 每次修改都新增一个版本，旧版仍读得到。轮换是「新增版本」，不是覆盖。 |
| **引用（`sref_…`）** | 条目的固定地址，例如 `https://…/v1/secrets/sref_7Qn4…`。**它本身不授予任何权限**，贴到工单或配置文件都安全。 |
| **Token（`bsct_…`）** | Agent 用来验证身份的东西。有范围、有期限、可撤销、有速率上限。签发时只显示一次。**它才是凭据。** |
| **范围** | 一把 token 能碰到的路径前缀与标签。`prod` 涵盖 `prod/` 底下全部。范围以外的条目，连列都列不出来。 |
| **审批** | 高价值条目每次被读取前都要问过人。Agent 会等，不会失败。 |
| **预授权** | 你审批过一次之后，那把 token 读那个条目就不再打扰你，直到预授权到期。也可以事先给。 |
| **任务窗口** | 把工作交给 Agent 之前开的一段时间窗。窗口内、范围内的读取只记录、不打扰你。它不会自己延长。 |
| **审计链** | 一份只能追加的账本，每条记录都含前一条的哈希值。任何篡改都会断链，看得出来。 |

由此衍生出两条值得记住的规则：

- **引用 URL 不是敏感数据，token 才是。** URL 会出现在 shell 历史、日志、Agent 对话里，那没关系——因为单靠 URL 什么都取不到。
- **没有人能救回你的口令。** 维护者不行、管理员不行、AI 助手也不行。请备份保险库文件。

## 2. 最初五分钟

1. 打开 <http://127.0.0.1:8787/>（或你的服务器网址），用口令**解封**。口令只会发送到那台机器上的服务，不会去别的地方。
2. 点**新建敏感数据**。填路径（例如 `prod/gcp`）、名称（例如 `firebase-admin`）、选类型，然后粘贴内容——或把凭据文件直接拖到输入框上。内容加密后才会写进磁盘。
3. 点 **📋 复制引用**。你拿到一个可以贴到任何地方的 URL，它本身取不到东西。
4. 到 **Agent Token → 签发 token**。标签写清楚是给哪个 Agent，路径范围不要超过那个 Agent 的工作，寿命不要超过那份工作。`bsct_…` 的值**只显示一次**——直接放进 Agent 的配置文件。
5. 把引用交给 Agent，让它去读。然后在**审计链**看到那条读取出现。

## 3. 界面导览

由左到右共七个标签页。

### 🏠 总览

条目数量、30 天内到期的东西、待审批数、进行中的任务窗口、有效 token，以及审计链状态。版本那一行会显示构建号，例如 `0.1.0+f23d51a`——升级后如果某台机器行为怪怪的，这行很有用。**更换口令**也在这里。

### 🗂️ 敏感数据

列表，左边是路径树，上面可按类型与环境筛选。搜索涵盖名称、路径、标签；它走的是盲索引，所以搜索词本身从来不会以明文存下来。按 `/` 直接跳到搜索框。

徽章告诉你这个条目特别在哪：

| 徽章 | 意思 |
| --- | --- |
| 🔴 | 每次读取都要你审批 |
| 🏠 | 只能在这个 UI 审批，不走外部通道 |
| 🔗 | 设了**使用绑定**：Agent 可以用它，但看不到它 |
| 🔄 | 轮换已逾期 |

点开条目有四个标签页：**详细**（元数据、到期日、轮换周期、删除）、**版本历史**（历史记录、新增版本）、**使用绑定**（第 7 节）、**审计记录**（这个条目的所有事件）。

**显示**会把值显示几秒后自动隐藏。需要审批的条目，要再输入一次口令。复制会把值放进剪贴板——用完记得清空剪贴板。

### 🎫 Agent Token

签发、查看、撤销。每把 token 有标签、范围、寿命、可选的读取次数上限，以及每分钟速率上限。列表会标示有效、过期或已撤销，以及剩余配额。**撤销**立即生效。

这个标签页上的**预先授权**面板请看第 5 节。

### 🔔 审批收件箱

待办列表。每一条会显示哪把 token 想读哪个条目、Agent 给的理由、已经升级过几阶、以及自动拒绝的倒计时。按 `a` 批准、`d` 拒绝。批准的同时会发出一张预授权，让同一把 token 在预授权到期前不会再为同一个条目问你。

### ▶️ 任务窗口

把工作交给 Agent 之前先开一个窗口：一个范围加一段时长（15 分钟到 2 小时，硬上限 8 小时）。窗口内的读取只记录、不打扰。窗口不会自己延长；一到期，提示就回来。

### ⏰ 到期追踪

条目与 token 按到期时间排序。用它在东西坏掉之前轮换，而不是坏掉之后。

### ⛓️ 审计链

所有事件：解封、创建、读取、签发、撤销、批准、删除、迁移。**重新验证**会重算整条链，报告「完整」或断在第几条。链里有条目 id、执行者、理由——没有任何值。

## 4. 日常操作

**新增凭据。** 新建敏感数据 → 路径、名称、类型、标签、内容。可选：到期日、以天为单位的轮换周期、以及「每次读取都需要我审批」。

**轮换。** 打开条目 → 版本历史 → 新增版本。旧版仍读得到，Agent 拿到的是新版，轮换时钟重新计算。在详细标签页设置周期天数后，逾期就会出现 🔄 徽章。

**决定哪些要审批。** 服务账户、云端 root 密钥、签名证书默认需要审批；登录账号密码与一般 API Key 不需要。可以逐条调整。如果觉得提示太频繁，那是「该用任务窗口或预先授权」的信号，不是「该关掉审批」的信号。

**删除。** 详细 → 删除条目，并填理由。密文、版本、索引行、预授权都会被移除。审计链保留历史：`item_deleted`、谁做的、为什么。没有恢复。

**更换口令。** 总览 → 更换口令。所有数据密钥会在单一事务内重新包封、索引重建；旧口令立刻失效，所有人被登出。条目内容本身不需要重新加密，所以就算保险库很大也很快。

**上锁。** 点**上锁**会立刻把保险库封起来：密钥离开内存、Agent 收到 `vault_sealed`、下一次读取要等人来解封。离开共享机器时请这么做。

## 5. 给 Agent 授权

四个旋钮。先转小，需要再转大。

| 旋钮 | 该设成 |
| --- | --- |
| **范围** | 能涵盖这份工作的最窄路径前缀。是 `prod/mobile`，不是 `prod`。 |
| **寿命** | 不超过工作本身。助手给一天，流水线给一小时。 |
| **读取次数上限** | 流水线要读三个敏感数据，就设 3。 |
| **速率上限** | 默认每分钟 60 已经很宽松；给机器用可以调低。 |

一个 Agent、一个项目，一把 token。这样撤销一次只影响一个 Agent 的一个项目，而审计链也说得出是谁做了什么。

**续期。** Token 只能在寿命的最后四分之一（再加五分钟宽限）内自行延长，而且永远不能超过硬上限。续期不会扩大范围。

**预先授权。** 如果你知道 Agent 在这次运行中会需要某个需审批的条目，就事先给：Agent Token → 预先授权 → 选 token、选条目、选时长。它以 token 的到期时间为上限，你随时可以撤回。这是「不要在不方便的时候被问」而又「不必为所有人放宽那个条目」的做法。

## 6. 审批，以及不被它拖垮

当需审批的条目被读取时，Agent 收到「等待中」并开始等。你则会收到一串提醒阶梯：

| 阶 | 时间 | 动作 |
| --- | --- | --- |
| 1 | 立刻 | 桌面通知 |
| 2 | 20 秒后 | 再通知一次，加上声音 |
| 3 | 60 秒后 | 外部通道（若有配置，例如 Telegram） |
| — | 5 分钟后 | **自动拒绝**并记录 |

每一阶都会写进审计链，所以就算是在时间压力下做的决定，事后也看得见。

外部通道只对外连接。消息会写出条目与理由，但绝不含内容值，也不含任何按下去就能取得内容的链接。标记为**仅限本机审批**的条目会在那里通知，但只能在 UI 审批。

审批疲劳是安全问题，不只是烦：一个条件反射式点下「批准」的人，比没有审批机制更糟。如果你被问得太频繁，就在工作期间开一个**任务窗口**，或针对那个条目与那把 token 做**预先授权**。两者都有边界、都有记录。「干脆关掉审批」是最后才该考虑的选项。

## 7. 让 Agent 用得到、却看不到

有些条目只会被发送到单一服务——部署密钥、webhook token 之类——你可以把它绑到那个服务，而不是把值交出去。

打开条目 → **使用绑定** → 填允许的 URL 模式（只接受 `https://`，结尾 `*` 表示前缀）、header 模板（例如 `Authorization: Bearer {value}`）、允许的方法。

之后 Agent 调用 `use_secret`，带上 URL 与内容。服务会替换凭据、自己发出请求、把对方的响应交回去。值不会进到 Agent、不会进到对话、不会进到日志。绑定范围外的请求会被拒绝，非 HTTPS 的网址与内部地址也一样。

清除绑定就回到一般读取模式。

## 8. 证明发生过什么，以及把数据带走

**验证审计链。** 审计链 → 重新验证；或在保险库上锁状态下离线运行：

```sh
bsc audit --vault ~/.bsc/vault.bsc
```

**锚定。** 验证能证明没有记录被**改过**，但拥有文件的人理论上可以把末尾几条删掉。锚定就是把链长与链首记到保险库之外：

```sh
bsc audit --anchor-file ~/anchors/bsc.jsonl
```

那个文件要放在保险库拥有者无法静默改写的地方：另一块磁盘、日志转发系统、git 仓库。在服务器上，用[安装手册](install.md)第 4.6 节的 timer 每天跑一次。

**Break-glass 导出。** 把所有条目、所有版本完整导出，并用**另一组**口令封装：

```sh
bsc export --out ~/bsc-export-2026-09-04.bscx
bsc import --in ~/bsc-export-2026-09-04.bscx     # 导入另一个保险库
```

它会拒绝沿用保险库口令，也拒绝覆盖已有文件。封装内容没有任何明文。Token、任务窗口、审批记录、审计链刻意不导出：导入是「用同一批凭据重新开始」，不是复制一份授权状态。

导出文件请比照保险库本身看待：加密、放在机器之外、绝不进仓库。

## 10. 值得养成的习惯

1. 口令自己输入。其他任何人——不管是人还是 AI——永远都不需要它。
2. 绝不把 `bsct_…` token 贴进对话。它该待在配置文件里。
3. 签发范围窄、寿命短的 token，工作结束就撤销。
4. 备份保险库文件，在别的机器留一份，并且实际用 `bsc audit` 读过那份备份。
5. 没事的时候也偶尔翻翻审计链。那是你认识「正常长什么样」的唯一方法。

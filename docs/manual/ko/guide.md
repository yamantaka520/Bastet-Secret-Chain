# 사용자 가이드

**적용 대상:** Bastet Secret Chain 0.2.0
**언어:** [繁體中文](../zh-Hant/guide.md) · [简体中文](../zh-Hans/guide.md) · [English](../en/guide.md) · [日本語](../ja/guide.md) · **한국어**
**함께 보기:** [설치](install.md) · [에이전트 가이드](agents.md)

이 가이드는 보관소(볼트)를 소유한 사람을 위한 것입니다. 자격 증명을 넣고, 어떤
에이전트가 무엇을 읽을 수 있는지 정하고, 승인 요청에 답하고, 사후에 누가 무엇을
읽었는지 증명하는 방법을 다룹니다.

---

## 1. 핵심 개념, 표 하나로

| 용어 | 의미 |
| --- | --- |
| **보관소(볼트)** | 암호화된 파일 하나입니다. *잠김*은 키가 메모리에 없어 아무것도 읽을 수 없는 상태를 뜻하며, 이는 소유자 본인에게도 마찬가지입니다. *봉인 해제됨*은 사람이 패스프레이즈를 입력했다는 뜻입니다. |
| **항목** | 자격 증명 하나입니다. 로그인 정보, API 키, 서비스 계정 JSON, SSH 키 등입니다. 경로, 이름, 유형, 태그를 가집니다. |
| **버전** | 변경할 때마다 버전이 추가되며 이전 버전도 계속 읽을 수 있습니다. 회전은 덮어쓰기가 아니라 버전을 추가하는 것입니다. |
| **참조 (`sref_…`)** | 항목의 안정적인 주소입니다. 예: `https://…/v1/secrets/sref_7Qn4…`. **그 자체로는 어떤 권한도 부여하지 않습니다.** 티켓이나 설정 파일에 붙여 넣어도 안전합니다. |
| **토큰 (`bsct_…`)** | 에이전트가 인증에 사용하는 값입니다. 범위(스코프)가 제한되고, 만료되며, 취소할 수 있고, 속도 제한이 걸립니다. 발급 시점에 정확히 한 번만 표시됩니다. 이것은 *실제* 자격 증명입니다. |
| **범위(스코프)** | 토큰이 접근할 수 있는 경로 접두사와 태그입니다. `prod`는 `prod/` 아래 전부를 포함합니다. 그 밖의 것은 목록에조차 나오지 않습니다. |
| **승인** | 가치가 높은 항목은 읽을 때마다 사람에게 묻습니다. 에이전트는 기다릴 뿐, 실패하지 않습니다. |
| **사전 승인/권한 부여** | 한 번 승인하고 나면 해당 토큰은 권한 부여가 만료될 때까지 그 항목을 묻지 않고 읽을 수 있습니다. 미리 부여해 둘 수도 있습니다. |
| **작업 세션** | 에이전트에게 일을 맡기기 전에 여는 시간 창입니다. 그 창과 범위(스코프) 안에서 일어난 읽기는 사용자를 방해하지 않고 기록됩니다. 세션이 스스로 연장되는 일은 없습니다. |
| **감사 체인** | 각 레코드가 이전 레코드의 해시를 담고 있는 추가 전용 원장입니다. 어떤 편집이든 체인을 깨뜨리며 곧바로 드러납니다. |

여기서 두 가지 규칙이 따라 나오며, 한 번쯤 익혀 둘 가치가 있습니다.

- **참조 URL은 시크릿이 아닙니다. 토큰이 시크릿입니다.** URL은 셸 히스토리, 로그,
  에이전트 대화 기록에 남게 마련이며, URL만으로는 아무것도 넘겨주지 않으므로 그래도
  괜찮습니다.
- **패스프레이즈는 아무도 복구할 수 없습니다.** 메인테이너도, 관리자도, AI
  어시스턴트도 마찬가지입니다. 보관소(볼트) 파일을 백업하십시오.

## 2. 처음 5분

1. <http://127.0.0.1:8787/>(또는 사용 중인 서버 주소)을 열고 패스프레이즈로
   **봉인을 해제**하십시오. 패스프레이즈는 그 머신의 데몬으로만 전달되며 다른 어디에도
   가지 않습니다.
2. **New secret**을 누르십시오. `prod/gcp` 같은 경로와 `firebase-admin` 같은 이름을
   채우고, 유형을 고른 다음 값을 붙여 넣으십시오 — 또는 자격 증명 파일을 필드 위로
   바로 끌어다 놓으십시오. 값은 디스크에 닿기 전에 암호화됩니다.
3. **📋 Copy reference**를 누르십시오. 이제 어디에나 붙여 넣을 수 있는 URL이
   생겼습니다. 그 자체로는 아무것도 넘겨주지 않습니다.
4. **Agent tokens → Mint token**으로 이동하십시오. 에이전트를 지칭하는 레이블, 그
   에이전트의 업무보다 넓지 않은 경로 범위(스코프), 작업 기간보다 길지 않은 수명을
   지정하십시오. `bsct_…` 값은 **한 번만** 표시됩니다 — 곧바로 에이전트의 설정 파일에
   넣으십시오.
5. 에이전트에게 참조를 건네고 읽게 하십시오. 그 읽기가 **Audit chain**에 나타나는
   것을 확인하십시오.

## 3. 인터페이스

왼쪽부터 오른쪽으로 일곱 개의 탭이 있습니다.

### 🏠 Overview

항목 수, 30일 이내에 만료되는 것, 대기 중인 승인, 활성 작업 세션, 유효한 토큰, 그리고
감사 체인의 상태를 보여줍니다. 버전 줄에는 빌드가 표시됩니다(예: `0.2.0+f23d51a`).
업그레이드 후 어떤 머신이 예상과 다르게 동작할 때 유용합니다. 여기에는 **Change
passphrase**도 있습니다.

### 🗂️ Secrets

경로 트리와 유형·환경 필터가 있는 목록입니다. 검색은 이름, 경로, 태그를 대상으로
하며, 블라인드 인덱스를 통해 동작하므로 검색어가 평문으로 저장되는 일은 없습니다.
`/`를 누르면 검색으로 바로 이동합니다.

배지는 항목의 특별한 점을 알려 줍니다.

| 배지 | 의미 |
| --- | --- |
| 🔴 | 읽을 때마다 사용자의 승인이 필요함 |
| 🏠 | 이 UI에서만 승인 가능 — 외부 채널 없음 |
| 🔗 | *사용 바인딩*이 있음: 에이전트가 값을 보지 않고 사용할 수 있음 |
| 🔄 | 회전 기한이 지남 |

항목을 열면 네 개의 탭이 나옵니다. **Detail**(메타데이터, 만료, 회전 주기, 삭제),
**Versions**(이력, 새 버전 추가), **Use binding**(7절), **Audit**(이 항목에 대한 모든
이벤트)입니다.

**Reveal**은 값을 몇 초 동안 보여 준 뒤 다시 숨깁니다. 승인이 필요한 항목이라면
패스프레이즈를 다시 입력해야 합니다. 복사하면 값이 클립보드에 들어가므로, 사용 후
클립보드를 비우십시오.

### 🎫 Agent tokens

발급, 조회, 취소를 합니다. 각 토큰에는 레이블, 범위(스코프), 수명, 선택적인 읽기
할당량, 분당 속도 제한이 있습니다. 목록에는 어떤 토큰이 유효한지, 만료되었는지,
취소되었는지, 그리고 할당량이 얼마나 남았는지가 표시됩니다. **Revoke**는 즉시
적용됩니다.

이 탭의 **Pre-authorizations** 패널은 5절에서 설명합니다.

### 🔔 Approvals

수신함입니다. 각 항목은 어떤 토큰이 어떤 항목을 원하는지, 에이전트가 제시한 이유,
지금까지 몇 단계의 알림이 지나갔는지, 그리고 자동 거부까지 남은 시간을 보여 줍니다.
`a`는 승인, `d`는 거부입니다. 승인하면 사전 승인/권한 부여도 함께 발급되어, 같은
토큰은 권한 부여가 만료될 때까지 그 항목에 대해 다시 묻지 않습니다.

### ▶️ Task sessions

에이전트에게 일을 맡기기 전에 시간 창을 여십시오. 범위(스코프)와 지속 시간(15분에서
2시간, 절대 상한은 8시간)을 지정합니다. 그 안에서 일어난 읽기는 묻지 않고 기록됩니다.
이 창은 스스로 연장되지 않으며, 끝나면 다시 승인 요청이 돌아옵니다.

### ⏰ Expiry

만료가 임박한 순서로 정렬된 항목과 토큰입니다. 무언가 망가진 뒤가 아니라 그 전에
회전하는 데 사용하십시오.

### ⛓️ Audit chain

모든 이벤트가 남습니다. 봉인 해제, 생성, 읽기, 발급, 취소, 승인, 삭제, 마이그레이션
등입니다. **Re-verify**는 체인 전체를 다시 계산하여 온전한지, 아니면 어느 레코드에서
끊어졌는지를 보고합니다. 체인에는 항목 id, 행위자, 이유가 담기며 값은 절대 담기지
않습니다.

## 4. 일상적인 작업

**자격 증명 추가.** New secret → 경로, 이름, 유형, 태그, 값. 선택 사항으로 만료일,
일 단위 회전 주기, *Ask me before every read*가 있습니다.

**회전.** 항목 열기 → Versions → Add version. 이전 버전은 계속 읽을 수 있고,
에이전트는 새 버전을 받으며, 회전 시계가 초기화됩니다. Detail 탭에서 일 단위 주기를
설정하면 기한이 지났을 때 🔄 배지가 나타납니다.

**무엇에 승인을 요구할지 정하기.** 서비스 계정, 클라우드 루트 키, 서명 인증서는
기본적으로 승인을 요구하며, 로그인 정보와 일반적인 API 키는 그렇지 않습니다. 항목별로
바꿀 수 있습니다. 너무 자주 묻는다면, 그것은 작업 세션이나 사전 승인/권한 부여를
쓰라는 신호이지 승인을 끄라는 신호가 아닙니다.

**삭제.** Detail → Delete item, 이유를 함께 적습니다. 암호문, 버전, 인덱스 행, 권한
부여가 함께 사라집니다. 원장에는 `item_deleted`와 누가 왜 삭제했는지가 이력으로
남습니다. 되돌릴 방법은 없습니다.

**패스프레이즈 변경.** Overview → Change passphrase. 모든 데이터 키가 다시 감싸지고
인덱스가 하나의 트랜잭션 안에서 재구성됩니다. 이전 패스프레이즈는 더 이상 동작하지
않으며 모두 로그아웃됩니다. 항목의 값 자체는 재암호화되지 않으므로, 보관소(볼트)가
커도 빠릅니다.

**잠그기.** **Lock**은 보관소(볼트)를 즉시 봉인합니다. 키가 메모리에서 사라지고,
에이전트는 `vault_sealed`를 받으며, 다음 읽기는 사람을 기다립니다. 공유 머신을 떠날
때 이렇게 하십시오.

## 5. 에이전트에게 접근 권한 주기

조절 손잡이는 네 개입니다. 올리기 전에 먼저 내려 두십시오.

| 손잡이 | 이렇게 설정 |
| --- | --- |
| **범위(스코프)** | 업무를 포괄하는 가장 좁은 경로 접두사. `prod`가 아니라 `prod/mobile`. |
| **수명** | 작업 기간보다 길지 않게. 어시스턴트에게는 하루, 파이프라인에는 한 시간. |
| **읽기 할당량** | 시크릿 세 개를 읽는 파이프라인이라면 3으로 설정. |
| **속도 제한** | 기본값인 분당 60은 넉넉합니다. 기계가 쓸 것이라면 더 낮추십시오. |

프로젝트마다, 에이전트마다 토큰 하나씩입니다. 그래야 토큰 하나를 취소해도 에이전트
하나의 프로젝트 하나에만 영향이 가고, 원장이 어느 에이전트가 무엇을 했는지 말해 줍니다.

**갱신.** 토큰은 수명의 마지막 4분의 1 구간(더하기 5분의 유예 기간) 안에서만 스스로
연장할 수 있으며, 절대 하드 상한을 넘지 못합니다. 갱신이 범위(스코프)를 넓히는 일은
없습니다.

**사전 승인.** 실행 중에 에이전트가 승인이 필요한 항목을 쓰게 될 것을 미리 안다면,
사전에 부여하십시오. Agent tokens → Pre-authorize → 토큰, 항목, 기간. 토큰의 만료
시각을 상한으로 하며 언제든 취소할 수 있습니다. 항목의 보호 수준을 모두에게 낮추지
않으면서 곤란한 순간에 질문을 받는 일을 피하는 방법이 바로 이것입니다.

## 6. 승인, 그리고 승인에 지치지 않기

승인이 필요한 항목을 읽으면 에이전트는 "pending"을 받고 기다립니다. 사용자에게는
단계적으로 알림이 옵니다.

| 단계 | 시점 | 일어나는 일 |
| --- | --- | --- |
| 1 | 즉시 | 데스크톱 알림 |
| 2 | 20초 후 | 소리와 함께 재알림 |
| 3 | 60초 후 | 구성되어 있다면 외부 채널(Telegram) |
| — | 5분 후 | **자동 거부**되고 기록됨 |

모든 단계가 원장에 기록되므로, 시간 압박 속에 내린 결정도 사후에 그대로 드러납니다.

외부 채널은 아웃바운드 전용입니다. 메시지는 항목과 이유를 밝히며, 값이나 값을 넘겨줄
링크는 절대 담지 않습니다. **로컬 승인 전용**으로 표시된 항목은 그곳에 알림은 가지만
승인은 UI에서만 할 수 있습니다.

승인 피로는 성가심이 아니라 보안 문제입니다. 반사적으로 Approve를 누르는 사람은 승인
절차가 아예 없는 것보다 나쁩니다. 너무 자주 묻는다면, 작업 기간 동안 **작업 세션**을
열거나 해당 항목과 토큰을 **사전 승인**하십시오. 둘 다 범위가 정해져 있고 둘 다
기록됩니다. 승인을 완전히 끄는 것은 가장 마지막에 꺼낼 선택지입니다.

## 7. 에이전트가 시크릿을 보지 않고 사용하게 하기

배포 키나 웹훅 토큰처럼 오직 한 서비스로만 전송되는 항목이라면, 값을 넘겨주는 대신 그
서비스에 바인딩할 수 있습니다.

항목 열기 → **Use binding** → 허용할 URL 패턴(`https://`만 가능, 접두사로 쓰려면
끝에 `*`), `Authorization: Bearer {value}` 같은 헤더 템플릿, 그리고 허용할 메서드를
지정합니다.

그러면 에이전트는 URL과 본문을 담아 `use_secret`을 호출합니다. 데몬이 자격 증명을
대입해 요청을 직접 보내고 서비스의 응답을 돌려줍니다. 값은 에이전트에도, 대화
기록에도, 로그에도 들어가지 않습니다. 바인딩을 벗어난 요청은 거부되며, HTTPS가 아닌
URL과 내부 주소도 마찬가지로 거부됩니다.

바인딩을 지우면 일반적인 읽기 방식으로 돌아갑니다.

---

## 8. 무슨 일이 있었는지 증명하고, 데이터를 꺼내기

**체인 검증.** Audit chain → Re-verify, 또는 보관소(볼트)가 잠긴 상태에서
오프라인으로 다음을 실행합니다.

```sh
bsc audit --vault ~/.bsc/vault.bsc
```

**앵커.** 검증은 아무것도 *편집되지* 않았음을 증명하지만, 파일 소유자는 원리상 끝부분의
레코드를 잘라낼 수 있습니다. 앵커링은 체인 길이와 헤드를 보관소(볼트) 바깥에
기록합니다.

```sh
bsc audit --anchor-file ~/anchors/bsc.jsonl
```

그 파일은 보관소(볼트) 소유자가 몰래 다시 쓸 수 없는 곳에 두십시오. 다른 디스크, 로그
수집기, git 저장소 같은 곳입니다. 서버에서는 [설치 매뉴얼](install.md)의 타이머로
매일 실행하십시오.

**비상용 내보내기.** 모든 항목과 모든 버전을 *다른* 패스프레이즈로 봉인해 통째로
내보냅니다.

```sh
bsc export --out ~/bsc-export-2026-09-04.bscx
bsc import --in ~/bsc-export-2026-09-04.bscx     # into another vault
```

보관소(볼트) 패스프레이즈를 재사용하는 것을 거부하고, 파일을 덮어쓰는 것도 거부합니다.
번들에는 평문이 들어 있지 않습니다. 토큰, 세션, 승인, 원장은 의도적으로 내보내지
않습니다. 가져오기는 같은 자격 증명으로 새로 시작하는 것이지, 인가 상태를 복제하는 것이
아닙니다.

내보낸 파일도 보관소(볼트) 자체와 똑같이 다루십시오. 암호화하고, 해당 머신 밖에 두고,
저장소에는 절대 넣지 마십시오.

## 10. 지킬 만한 습관

1. 패스프레이즈는 본인이 직접 입력하십시오. 사람이든 AI든, 다른 누구도 그것을 알 필요는
   결코 없습니다.
2. `bsct_…` 토큰을 채팅에 붙여 넣지 마십시오. 토큰이 있어야 할 곳은 설정 파일입니다.
3. 좁고 짧은 토큰을 발급하고, 작업이 끝나면 취소하십시오.
4. 보관소(볼트) 파일을 백업하고, 사본 하나는 해당 머신 밖에 두고, `bsc audit`가 그
   백업을 읽을 수 있는지 확인하십시오.
5. 아무 문제가 없을 때도 가끔 원장을 읽어 보십시오. 그렇게 해야 정상이 어떤 모습인지
   알게 됩니다.

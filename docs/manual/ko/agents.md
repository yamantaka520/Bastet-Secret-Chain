# AI 에이전트 가이드

**적용 대상:** Bastet Secret Chain 0.1.0
**언어:** [繁體中文](../zh-Hant/agents.md) · [简体中文](../zh-Hans/agents.md) · [English](../en/agents.md) · [日本語](../ja/agents.md) · **한국어**
**함께 보기:** [설치](install.md) · [사용자 가이드](guide.md) · [API 계약](../../API_CONTRACT.md)

이것이 이 프로젝트의 핵심입니다. 에이전트는 필요한 시크릿을 필요한 그 순간에 정확히
그만큼만 가져오며, 시크릿은 프롬프트에도, URL에도, 셸 히스토리에도, 대화 기록에도
절대 나타나지 않습니다.

---

## 1. 올바른 통합이란

1. **사람**이 UI에서 범위(스코프)가 제한되고 만료되는 토큰을 발급하여 에이전트의 **설정
   파일**에 넣습니다 — 프롬프트, 저장소, URL에는 절대 넣지 않습니다.
2. 에이전트는 `curl`이 아니라 **MCP 서버**를 통해 보관소(볼트)에 접근합니다.
3. 에이전트의 지시문은 실제 이유를 제시하고, 읽기가 대기 중이면 기다리며, 사람에게
   시크릿을 붙여 넣어 달라고 절대 요청하지 않도록 지시합니다.
4. 사람이 모든 읽기를 원장에서 보고, 가치가 높은 읽기는 그전에 수신함에서 먼저 봅니다.

이 네 가지 중 하나라도 빠져 있다면, 동작하더라도 그 통합은 잘못된 것입니다.

원시 HTTP가 아니라 MCP를 쓰는 이유는 이렇습니다. 도구 설명은 모델이 실제로 읽는
명세이고, 값이 셸을 거치지 않으며, 토큰이 에이전트가 생성하는 명령에 나타나지
않습니다. HTTP API는 여전히 단일 진실 공급원이자 유일한 감사 진입점으로 남으며, CI와
MCP를 지원하지 않는 모든 것을 위해 존재합니다.

---

## 2. 에이전트 연결하기

MCP 서버는 같은 바이너리입니다. `bsc mcp`가 stdio를 통해 실행 중인 데몬과 통신합니다.
URL과 토큰을 환경 변수나 `0600` 파일로 전달하십시오.

**Claude Code** — 프로젝트의 `.mcp.json`(토큰은 **빼고** 커밋) 또는 `~/.claude.json`:

```json
{
  "mcpServers": {
    "bsc": {
      "command": "bsc",
      "args": ["mcp", "--url", "http://127.0.0.1:8787"],
      "env": { "BSC_TOKEN": "${BSC_TOKEN}" }
    }
  }
}
```

**Codex CLI** — `~/.codex/config.toml`:

```toml
[mcp_servers.bsc]
command = "bsc"
args = ["mcp", "--url", "http://127.0.0.1:8787", "--token-file", "/home/you/.bsc/tokens/codex"]
```

**Gemini CLI / Agy** — `~/.gemini/settings.json`:

```json
{ "mcpServers": { "bsc": { "command": "bsc", "args": ["mcp"], "env": { "BSC_TOKEN": "$BSC_TOKEN" } } } }
```

원격 보관소(볼트)를 쓰려면 `"--url", "https://secrets.example.com"`을 사용하십시오.
프로젝트마다 서버 항목을 하나씩 두고, 각각 좁게 제한된 자체 토큰을 주십시오. 그러면
프로젝트 A에서 일하는 에이전트는 프로젝트 B의 항목을 나열조차 할 수 없습니다.

## 3. 여섯 개의 도구

모두 읽기 전용입니다. 무언가를 만들거나, 편집하거나, 삭제하는 도구는 없습니다. 그것은
UI에서 사람이 하는 일입니다.

| 도구 | 입력 | 결과 |
| --- | --- | --- |
| `list_secrets` | `path?`, `tag?` | 범위(스코프) 안의 항목: 참조, 이름, 경로, 유형, 태그, 만료, 승인 필요 여부. **값은 절대 포함되지 않습니다.** |
| `get_secret` | `sref`, `reason` | 값, 그 버전, 그리고 경고가 있으면 함께 — 또는 `approval_pending`. |
| `request_access` | `sref`, `reason` | 기다릴 대상이 되는 승인 id. |
| `check_access` | `approval_id`, `wait_seconds?` (≤ 60) | 결정 내용, 그리고 승인된 경우 값을 한 번. |
| `use_secret` | `sref`, `reason`, `url`, `method?`, `headers?`, `body?` | 상위 서비스의 응답. 자격 증명은 데몬이 주입하며 에이전트에는 절대 닿지 않습니다. |
| `renew_access` | — | 호출한 토큰의 만료 시각을 뒤로 미룹니다. 범위(스코프)를 넓히는 일은 없습니다. |

`reason`은 필수이며 원장에 기록됩니다. "deploy staging from commit abc123"은 이유이지만,
"task"는 이유가 아닙니다.

## 4. 에이전트에게 알려 줄 내용

다음을 `CLAUDE.md`, `AGENTS.md` 또는 이에 준하는 파일에 그대로 넣으십시오.

> 자격 증명은 `bsc` MCP 서버에서 가져온다. `list_secrets`로 항목을 찾은 다음, 지금
> 무엇을 하려는지 밝히는 `reason`과 함께 `get_secret`을 호출한다. 그 값은 살아 있는
> 자격 증명이다. 절대 파일에 쓰거나, 출력하거나, 셸 명령에 echo하거나, 응답에 다시
> 옮겨 적지 않는다. 호출이 `approval_pending`을 반환하면 `wait_seconds: 60`으로
> `check_access`를 호출하고 계속 기다린다 — 사용자에게 시크릿을 붙여 넣어 달라고
> 요청하지 말고, 원래 호출을 반복해서 재시도하지도 않는다. 결과에 토큰 만료 경고가
> 실려 있으면 다음번 자연스러운 지점에서 `renew_access`를 호출한다. 항목에 사용
> 바인딩이 있으면 값을 읽는 대신 `use_secret`을 사용한다.

가장 중요한 단 한 문장은 사람에게 시크릿을 붙여 넣어 달라고 요청하지 **말라고** 지시하는
문장입니다. 이 설계 전체가 존재하는 이유가 바로 그 실패 양상을 막기 위해서입니다.

## 5. 스크립트와 CI

MCP 클라이언트가 없는 곳에서는 HTTP API를 호출하십시오. 토큰은 CI 시크릿 저장소에
두고, 이유는 URL이 아니라 헤더에 담습니다.

```sh
curl -fsS -H "Authorization: Bearer $BSC_TOKEN" \
     -H "X-BSC-Reason: deploy $GITHUB_SHA to staging" \
     "$BSC_URL/v1/secrets/$SREF" | jq -r .value
```

세 가지 응답을 처리하십시오.

- `200` — 값은 `.value`에 있습니다(바이너리는 `.value_base64`).
- `202 approval_pending` — `Retry-After`를 지키면서 결정이 날 때까지 승인을 폴링합니다.
  `denied`나 `timeout`이면 명확히 로그를 남기고 중단합니다.
- `renewable: true`가 함께 온 `401 token_expired` — `POST /v1/token/renew` 후 한 번만
  재시도합니다.

그 밖의 모든 것은 회복 불가능한 실패입니다. 본문의 `next_action`을 출력하십시오. 이는
로그를 보는 사람이 읽도록 작성된 것입니다.

파이프라인마다 전용 토큰을 쓰고, 읽기 할당량은 그 작업에 맞게, 수명은 그 스케줄보다
길지 않게 잡으십시오. 회전은 새 토큰을 발급하고 기존 것을 취소하는 방식으로 합니다.

## 6. 오류 코드

모든 오류에는 기계가 읽을 수 있는 `error`, 사람이 읽을 `message`, `next_action`,
그리고 `do_not`이 함께 실립니다. 마지막 것이 존재하는 이유는, 구분되지 않은 `401`을
받은 에이전트는 임기응변을 시도하는데 그중 최악이 사람에게 채팅 창에 자격 증명을 붙여
넣어 달라고 요청하는 것이기 때문입니다.

| 코드 | HTTP | 에이전트가 해야 할 일 |
| --- | --- | --- |
| `approval_pending` | 202 | `check_access`로 기다립니다. 반복 재시도하지 않습니다. |
| `approval_denied` | 403 | 중단하고 보고합니다. 다른 이유를 붙여 다시 요청하지 않습니다. |
| `approval_timeout` | 408 | 아무도 응답하지 않았음을 보고합니다. 반복하지 않습니다. |
| `token_expired` | 401 | 갱신한 뒤 한 번만 재시도합니다. 시크릿을 붙여 넣어 달라고 요청하지 않습니다. |
| `token_revoked` | 401 | 중단하고 사용자에게 재발급을 요청합니다. 다른 곳을 찾지 않습니다. |
| `scope_mismatch` | 403 | 무엇이 필요한지 말합니다. 다른 참조를 탐색하지 않습니다. |
| `quota_exhausted` | 429 | 중단하고 사용자에게 알립니다. |
| `rate_limited` | 429 | `retry_after`만큼 기다립니다. 반복 주기를 더 좁히지 않습니다. |
| `vault_sealed` | 503 | 사람이 UI에서 봉인을 해제해야 한다고 말합니다. 보관소(볼트) 패스프레이즈를 **절대** 요청하지 않습니다. |
| `not_found` | 404 | `list_secrets`로 다시 확인합니다. 참조를 추측하지 않습니다. |
| `reason_required` | 400 | 구체적인 이유를 붙여 다시 요청합니다. 자리 표시자는 안 됩니다. |
| `use_not_configured` | 400 | 사람에게 항목을 바인딩해 달라고 요청하거나, 정말로 필요하다면 값을 읽습니다. |
| `use_not_allowed` | 403 | 어떤 URL이 필요한지 말합니다. 다른 URL을 탐색하지 않습니다. |
| `upstream_failed` | 502 | 한 번 재시도한 뒤 보고합니다. 서비스를 직접 호출하겠다며 시크릿을 요청하지 않습니다. |

## 7. 무언가 잘못되었을 때

| 에이전트가 하는 말 | 의미 | 할 일 |
| --- | --- | --- |
| "unauthorized" | 토큰이 인식되지 않음 | `BSC_TOKEN`, `--token-file`, URL을 확인하십시오 |
| "token_expired, renewable: false" | 갱신 가능 구간이 지남 | UI에서 새 토큰을 발급하십시오 |
| "scope_mismatch" | 보관소(볼트)는 맞지만 토큰이 틀림 | 범위(스코프)를 넓히거나 그 경로용 토큰을 발급하십시오 |
| "approval_pending"이 오래 지속됨 | 아무도 승인하지 않음 | 수신함을 여십시오. 다음번에는 작업 세션을 고려하십시오 |
| "vault_sealed" | 데몬이 재시작됨 | UI에서 봉인을 해제하십시오. 에이전트가 패스프레이즈를 알게 해서는 절대 안 됩니다 |
| 시크릿을 붙여 넣어 달라고 요청함 | 지시문을 무시한 것 | 거부하십시오. 셸 도구가 아니라 정말로 `bsc mcp`를 쓰고 있는지 확인하십시오 |

## 8. 안티패턴

- 프롬프트, `CLAUDE.md`, 커밋된 `.env`, URL에 들어 있는 `bsct_…` 토큰. 토큰은 자격
  증명입니다. 그에 맞게 다루십시오.
- 모든 에이전트가 공유하는 넓은 토큰 하나. 원장을 읽을 가치 있게 만드는 것이 바로
  범위(스코프)입니다.
- MCP를 쓸 수 있는데도 에이전트가 셸 도구로 API를 `curl`하게 두는 것. 값이 프로세스
  인수와 셸 히스토리에 남습니다.
- 파이프라인을 조용하게 만들려고 서비스 계정의 승인을 꺼 버리는 것. 대신 작업 세션을
  열거나 사전 승인하십시오. 둘 다 스스로 끝납니다.
- 실행을 막힘 없이 진행하려고 "이번 한 번만" 시크릿을 붙여 넣는 것. 그것이야말로 이
  시스템이 불필요하게 만들려고 만들어진 바로 그 사건입니다.

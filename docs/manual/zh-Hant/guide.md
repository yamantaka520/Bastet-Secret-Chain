# 使用手冊

**適用版本：**Bastet Secret Chain 0.2.0
**語言：** **繁體中文** · [简体中文](../zh-Hans/guide.md) · [English](../en/guide.md) · [日本語](../ja/guide.md) · [한국어](../ko/guide.md)
**延伸閱讀：**[安裝手冊](install.md) · [Agent 接入手冊](agents.md)

這份手冊寫給保險庫的擁有者：怎麼把憑證放進去、決定哪個 Agent 能讀什麼、怎麼回應核准請求，以及事後怎麼證明誰讀了什麼。

---

## 1. 觀念一次講完

| 名詞 | 意思 |
| --- | --- |
| **保險庫** | 一個加密檔案。**上鎖**代表金鑰不在記憶體裡，任何內容都讀不到——包括你自己。**解封**代表有人輸入過密語。 |
| **項目** | 一筆憑證：一組登入帳密、一把 API Key、一份服務帳戶 JSON、一把 SSH 金鑰。有路徑、名稱、類型、標籤。 |
| **版本** | 每次修改都新增一個版本，舊版仍讀得到。輪替是「新增版本」，不是覆蓋。 |
| **參照（`sref_…`）** | 項目的固定位址，例如 `https://…/v1/secrets/sref_7Qn4…`。**它本身不授予任何權限**，貼到工單或設定檔都安全。 |
| **Token（`bsct_…`）** | Agent 用來驗證身分的東西。有範圍、有期限、可撤銷、有速率上限。鑄造時只顯示一次。**它才是憑證。** |
| **範圍** | 一把 token 能碰到的路徑前綴與標籤。`prod` 涵蓋 `prod/` 底下全部。範圍以外的項目，連列都列不出來。 |
| **核准** | 高價值項目每次被讀取前都要問過人。Agent 會等，不會失敗。 |
| **授權** | 你核准過一次之後，那把 token 讀那個項目就不再打擾你，直到授權到期。也可以事先給。 |
| **任務窗口** | 把工作交給 Agent 之前開的一段時間窗。窗口內、範圍內的讀取只記錄、不打擾你。它不會自己延長。 |
| **稽核鏈** | 一份只能追加的帳本，每筆紀錄都含前一筆的雜湊值。任何竄改都會斷鏈，看得出來。 |

由此衍生出兩條值得記住的規則：

- **參照 URL 不是秘密，token 才是。** URL 會出現在 shell 歷史、記錄檔、Agent 對話裡，那沒關係——因為單靠 URL 什麼都取不到。
- **沒有人能救回你的密語。** 維護者不行、管理員不行、AI 助理也不行。請備份保險庫檔案。

## 2. 最初五分鐘

1. 打開 <http://127.0.0.1:8787/>（或你的伺服器網址），用密語**解封**。密語只會送到那台機器上的服務，不會去別的地方。
2. 按**新增機敏資料**。填路徑（例如 `prod/gcp`）、名稱（例如 `firebase-admin`）、選類型，然後貼上內容——或把憑證檔案直接拖到欄位上。內容加密後才會寫進磁碟。
3. 按 **📋 複製參照**。你拿到一個可以貼到任何地方的 URL，它本身取不到東西。
4. 到 **Agent Token → 鑄造 token**。標籤寫清楚是給哪個 Agent，路徑範圍不要超過那個 Agent 的工作，壽命不要超過那份工作。`bsct_…` 的值**只顯示一次**——直接放進 Agent 的設定檔。
5. 把參照交給 Agent，讓它去讀。然後在**稽核鏈**看到那筆讀取出現。

## 3. 介面導覽

由左到右共七個分頁。

### 🏠 總覽

項目數量、30 天內到期的東西、待核准數、進行中的任務窗口、有效 token，以及稽核鏈狀態。版本那一行會顯示建置編號，例如 `0.2.0+f23d51a`——升級後如果某台機器行為怪怪的，這行很有用。**更換密語**也在這裡。

### 🗂️ 機敏資料

清單，左邊是路徑樹，上面可依類型與環境過濾。搜尋涵蓋名稱、路徑、標籤；它走的是盲索引，所以搜尋詞本身從來不會以明文存下來。按 `/` 直接跳到搜尋框。

徽章告訴你這個項目特別在哪：

| 徽章 | 意思 |
| --- | --- |
| 🔴 | 每次讀取都要你核准 |
| 🏠 | 只能在這個 UI 核准，不走外部通道 |
| 🔗 | 設了**使用綁定**：Agent 可以用它，但看不到它 |
| 🔄 | 輪替已逾期 |

點開項目有四個分頁：**詳細**（中繼資料、到期日、輪替週期、刪除）、**版本歷史**（歷史紀錄、新增版本）、**使用綁定**（第 7 節）、**稽核紀錄**（這個項目的所有事件）。

**顯示**會把值顯示幾秒後自動隱藏。需要核准的項目，要再輸入一次密語。複製會把值放進剪貼簿——用完記得清空剪貼簿。

### 🎫 Agent Token

鑄造、檢視、撤銷。每把 token 有標籤、範圍、壽命、可選的讀取次數上限，以及每分鐘速率上限。清單會標示有效、過期或已撤銷，以及剩餘配額。**撤銷**立即生效。

這個分頁上的**預先授權**面板請看第 5 節。

### 🔔 核准收件匣

待辦清單。每一筆會顯示哪把 token 想讀哪個項目、Agent 給的理由、已經升級過幾階、以及自動拒絕的倒數。按 `a` 核准、`d` 拒絕。核准的同時會發出一張授權，讓同一把 token 在授權到期前不會再為同一個項目問你。

### ▶️ 任務窗口

把工作交給 Agent 之前先開一個窗口：一個範圍加一段時長（15 分鐘到 2 小時，硬上限 8 小時）。窗口內的讀取只記錄、不打擾。窗口不會自己延長；一到期，提示就回來。

### ⏰ 到期追蹤

項目與 token 依到期時間排序。用它在東西壞掉之前輪替，而不是壞掉之後。

### ⛓️ 稽核鏈

所有事件：解封、建立、讀取、鑄造、撤銷、核准、刪除、遷移。**重新驗證**會重算整條鏈，回報「完整」或斷在第幾筆。鏈裡有項目 id、執行者、理由——沒有任何值。

## 4. 日常操作

**新增憑證。** 新增機敏資料 → 路徑、名稱、類型、標籤、內容。選填：到期日、以天為單位的輪替週期、以及「每次讀取都需要我核准」。

**輪替。** 打開項目 → 版本歷史 → 新增版本。舊版仍讀得到，Agent 拿到的是新版，輪替時鐘重新計算。在詳細分頁設定週期天數後，逾期就會出現 🔄 徽章。

**決定哪些要核准。** 服務帳戶、雲端 root 金鑰、簽章憑證預設需要核准；登入帳密與一般 API Key 不需要。可以逐項調整。如果覺得提示太頻繁，那是「該用任務窗口或預先授權」的訊號，不是「該關掉核准」的訊號。

**刪除。** 詳細 → 刪除項目，並填理由。密文、版本、索引列、授權都會被移除。稽核鏈保留歷史：`item_deleted`、誰做的、為什麼。沒有復原。

**更換密語。** 總覽 → 更換密語。所有資料金鑰會在單一交易內重新包封、索引重建；舊密語立刻失效，所有人被登出。項目內容本身不需要重新加密，所以就算保險庫很大也很快。

**上鎖。** 按**上鎖**會立刻把保險庫封起來：金鑰離開記憶體、Agent 收到 `vault_sealed`、下一次讀取要等人來解封。離開共用機器時請這麼做。

## 5. 給 Agent 授權

四個旋鈕。先轉小，需要再轉大。

| 旋鈕 | 該設成 |
| --- | --- |
| **範圍** | 能涵蓋這份工作的最窄路徑前綴。是 `prod/mobile`，不是 `prod`。 |
| **壽命** | 不超過工作本身。助理給一天，流水線給一小時。 |
| **讀取次數上限** | 流水線要讀三個秘密，就設 3。 |
| **速率上限** | 預設每分鐘 60 已經很寬鬆；給機器用可以調低。 |

一個 Agent、一個專案，一把 token。這樣撤銷一次只影響一個 Agent 的一個專案，而稽核鏈也說得出是誰做了什麼。

**續期。** Token 只能在壽命的最後四分之一（再加五分鐘寬限）內自行延長，而且永遠不能超過硬上限。續期不會擴大範圍。

**預先授權。** 如果你知道 Agent 在這次執行中會需要某個需核准的項目，就事先給：Agent Token → 預先授權 → 選 token、選項目、選時長。它以 token 的到期時間為上限，你隨時可以撤回。這是「不要在不方便的時候被問」而又「不必為所有人放寬那個項目」的做法。

## 6. 核准，以及不被它拖垮

當需核准的項目被讀取時，Agent 收到「等待中」並開始等。你則會收到一串提醒階梯：

| 階 | 時間 | 動作 |
| --- | --- | --- |
| 1 | 立刻 | 桌面通知 |
| 2 | 20 秒後 | 再通知一次，加上聲音 |
| 3 | 60 秒後 | 外部通道（若有設定，例如 Telegram） |
| — | 5 分鐘後 | **自動拒絕**並記錄 |

每一階都會寫進稽核鏈，所以就算是在時間壓力下做的決定，事後也看得見。

外部通道只對外連線。訊息會寫出項目與理由，但絕不含內容值，也不含任何按下去就能取得內容的連結。標記為**僅限本機核准**的項目會在那裡通知，但只能在 UI 核准。

核准疲勞是安全問題，不只是煩：一個反射性按下「核准」的人，比沒有核准機制更糟。如果你被問得太頻繁，就在工作期間開一個**任務窗口**，或針對那個項目與那把 token 做**預先授權**。兩者都有邊界、都有紀錄。「乾脆關掉核准」是最後才該考慮的選項。

## 7. 讓 Agent 用得到、卻看不到

有些項目只會被送到單一服務——部署金鑰、webhook token 之類——你可以把它綁到那個服務，而不是把值交出去。

打開項目 → **使用綁定** → 填允許的 URL 樣式（只接受 `https://`，結尾 `*` 表示前綴）、header 模板（例如 `Authorization: Bearer {value}`）、允許的方法。

之後 Agent 呼叫 `use_secret`，帶上 URL 與內容。服務會替換憑證、自己送出請求、把對方的回應交回去。值不會進到 Agent、不會進到對話、不會進到記錄檔。綁定範圍外的請求會被拒絕，非 HTTPS 的網址與內部位址也一樣。

清除綁定就回到一般讀取模式。

## 8. 證明發生過什麼，以及把資料帶走

**驗證稽核鏈。** 稽核鏈 → 重新驗證；或在保險庫上鎖狀態下離線執行：

```sh
bsc audit --vault ~/.bsc/vault.bsc
```

**錨定。** 驗證能證明沒有紀錄被**改過**，但擁有檔案的人理論上可以把尾端幾筆砍掉。錨定就是把鏈長與鏈首記到保險庫之外：

```sh
bsc audit --anchor-file ~/anchors/bsc.jsonl
```

那個檔案要放在保險庫擁有者無法靜默改寫的地方：另一顆磁碟、log 轉送系統、git 版本庫。在伺服器上，用[安裝手冊](install.md)第 4.6 節的 timer 每天跑一次。

**Break-glass 匯出。** 把所有項目、所有版本完整匯出，並用**另一組**密語封裝：

```sh
bsc export --out ~/bsc-export-2026-09-04.bscx
bsc import --in ~/bsc-export-2026-09-04.bscx     # 匯入另一個保險庫
```

它會拒絕沿用保險庫密語，也拒絕覆蓋既有檔案。封裝內容沒有任何明文。Token、任務窗口、核准紀錄、稽核鏈刻意不匯出：匯入是「用同一批憑證重新開始」，不是複製一份授權狀態。

匯出檔請比照保險庫本身看待：加密、放在機器之外、絕不進版本庫。

## 10. 值得養成的習慣

1. 密語自己輸入。其他任何人——不管是人還是 AI——永遠都不需要它。
2. 絕不把 `bsct_…` token 貼進對話。它該待在設定檔裡。
3. 鑄造範圍窄、壽命短的 token，工作結束就撤銷。
4. 備份保險庫檔案，在別的機器留一份，並且實際用 `bsc audit` 讀過那份備份。
5. 沒事的時候也偶爾翻翻稽核鏈。那是你認識「正常長什麼樣」的唯一方法。

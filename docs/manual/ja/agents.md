# AI エージェントガイド

**対象:** Bastet Secret Chain 0.1.0
**言語:** [繁體中文](../zh-Hant/agents.md) · [简体中文](../zh-Hans/agents.md) · [English](../en/agents.md) · **日本語** · [한국어](../ko/agents.md)
**関連:** [インストール](install.md) · [ユーザーガイド](guide.md) · [API 契約](../../API_CONTRACT.md)

これこそがこのプロジェクトの目的です。エージェントは、必要なシークレットだけを、
必要なその瞬間に取得し、そのシークレットはプロンプト、URL、シェル履歴、対話記録の
どこにも現れません。

---

## 1. 正しい統合とはどういうものか

1. **人間**が UI でスコープ付きの有効期限付きトークンを発行し、それをエージェントの
   **設定ファイル**に置きます。プロンプト、リポジトリ、URL には決して置きません。
2. エージェントは `curl` 経由ではなく、**MCP サーバー**として保管庫に到達します。
3. エージェントへの指示には、実質的な理由を示すこと、読み取りが保留中なら待つこと、
   そして人にシークレットの貼り付けを頼まないことが書かれています。
4. 人間は台帳ですべての読み取りを確認でき、価値の高い読み取りはその前に受信箱で
   確認します。

この 4 つのうち 1 つでも欠けていれば、動いていても統合としては誤りです。

生の HTTP ではなく MCP を使う理由は、ツールの説明がモデルが実際に読む仕様として
機能し、値がシェルを通らず、トークンがエージェントの生成するコマンドに現れない
からです。HTTP API は引き続き唯一の信頼できる基準であり、唯一の監査の入口として、
CI や MCP を話せないものすべてのために存在します。

## 2. エージェントを接続する

MCP サーバーは同じバイナリです。`bsc mcp` は稼働中のデーモンと stdio で通信します。
URL と、環境変数または `0600` のファイルから読むトークンを与えてください。

**Claude Code** — プロジェクト内の `.mcp.json`（トークンを**含めずに**コミット）
または `~/.claude.json`:

```json
{
  "mcpServers": {
    "bsc": {
      "command": "bsc",
      "args": ["mcp", "--url", "http://127.0.0.1:8787"],
      "env": { "BSC_TOKEN": "${BSC_TOKEN}" }
    }
  }
}
```

**Codex CLI** — `~/.codex/config.toml`:

```toml
[mcp_servers.bsc]
command = "bsc"
args = ["mcp", "--url", "http://127.0.0.1:8787", "--token-file", "/home/you/.bsc/tokens/codex"]
```

**Gemini CLI / Agy** — `~/.gemini/settings.json`:

```json
{ "mcpServers": { "bsc": { "command": "bsc", "args": ["mcp"], "env": { "BSC_TOKEN": "$BSC_TOKEN" } } } }
```

リモートの保管庫には `"--url", "https://secrets.example.com"` を使います。
プロジェクトごとにサーバーのエントリを 1 つ、それぞれに狭くスコープを絞ったトークン
を持たせてください。そうすれば、プロジェクト A で作業するエージェントは、
プロジェクト B のアイテムを一覧することすらできません。

## 3. 6 つのツール

すべて読み取り専用です。作成、編集、削除を行うツールは存在しません。それらは UI で
人間が行う操作です。

| ツール | 入力 | 結果 |
| --- | --- | --- |
| `list_secrets` | `path?`, `tag?` | スコープ内のアイテム: 参照、名前、パス、種別、タグ、有効期限、承認が必要かどうか。**値は決して返しません。** |
| `get_secret` | `sref`, `reason` | 値、そのバージョン、および警告があればそれ。または `approval_pending`。 |
| `request_access` | `sref`, `reason` | 待機に使う承認 ID。 |
| `check_access` | `approval_id`, `wait_seconds?`（≤ 60） | 判断結果と、承認された場合は一度だけ値。 |
| `use_secret` | `sref`, `reason`, `url`, `method?`, `headers?`, `body?` | 上流サービスの応答。認証情報はデーモンが差し込み、エージェントには決して届きません。 |
| `renew_access` | — | 呼び出し元トークンの、より遅い有効期限。スコープを広げることはありません。 |

`reason` は必須で、台帳に記録されます。「deploy staging from commit abc123」は理由
ですが、「task」は理由ではありません。

## 4. エージェントに何を伝えるか

これを `CLAUDE.md`、`AGENTS.md` またはそれに相当するファイルに、そのまま書いて
ください。

> 認証情報は `bsc` MCP サーバーから取得します。`list_secrets` でアイテムを見つけ、
> これから何をするのかを述べた `reason` を添えて `get_secret` を呼びます。値は
> 実在する有効な認証情報です。ファイルに書き出したり、表示したり、シェルコマンドに
> echo したり、返答の中で繰り返したりしては決していけません。呼び出しが
> `approval_pending` を返した場合は、`wait_seconds: 60` を指定して `check_access`
> を呼び、待ち続けてください。私にシークレットの貼り付けを求めてはいけませんし、
> 元の呼び出しをループで再試行してもいけません。結果にトークンの有効期限に関する
> 警告が含まれていたら、次の自然な区切りで `renew_access` を呼んでください。
> アイテムに使用バインディングがある場合は、値を読むより `use_secret` を優先して
> ください。

最も重要な一文は、人にシークレットの貼り付けを求めては**いけない**とエージェントに
告げる部分です。この設計全体は、まさにその失敗モードを防ぐために存在しています。

## 5. スクリプトと CI

MCP クライアントがない場所では、HTTP API を呼びます。トークンは CI のシークレット
ストアに置き、理由はヘッダーに入れます。URL には決して入れません。

```sh
curl -fsS -H "Authorization: Bearer $BSC_TOKEN" \
     -H "X-BSC-Reason: deploy $GITHUB_SHA to staging" \
     "$BSC_URL/v1/secrets/$SREF" | jq -r .value
```

3 つの応答を処理してください。

- `200` — 値は `.value` にあります（バイナリの場合は `.value_base64`）。
- `202 approval_pending` — `Retry-After` を尊重しつつ、判断が下るまで承認をポーリング
  します。`denied` または `timeout` になったら明確にログを残して停止します。
- `401 token_expired` で `renewable: true` — `POST /v1/token/renew` を行い、一度だけ
  再試行します。

それ以外はすべて回復不能な失敗です。ボディにある `next_action` を出力してください。
これはログを見る人が読むことを想定して書かれています。

パイプラインごとのトークンを使い、読み取りクォータをその仕事に見合った大きさにし、
有効期限をそのスケジュールより長くしないでください。ローテーションは、新しい
トークンを発行して古いものを失効させることで行います。

## 6. エラーコード

どのエラーも、機械可読な `error`、人間向けの `message`、`next_action`、そして
`do_not` を持ちます。最後のものが存在するのは、区別のつかない `401` を受け取った
エージェントが即興で対処しようとし、その最悪の即興が、人にチャットウィンドウへ
認証情報を貼り付けるよう求めることだからです。

| コード | HTTP | エージェントが取るべき行動 |
| --- | --- | --- |
| `approval_pending` | 202 | `check_access` で待つ。ループで再試行しない。 |
| `approval_denied` | 403 | 停止して報告する。理由を変えて再度求めない。 |
| `approval_timeout` | 408 | 誰も応答しなかったと報告する。ループしない。 |
| `token_expired` | 401 | 更新してから一度だけ再試行する。シークレットの貼り付けを求めない。 |
| `token_revoked` | 401 | 停止し、再発行が必要だとユーザーに伝える。他を探し回らない。 |
| `scope_mismatch` | 403 | 何が必要かを述べる。他の参照を探らない。 |
| `quota_exhausted` | 429 | 停止してユーザーに伝える。 |
| `rate_limited` | 429 | `retry_after` だけ待つ。ループを詰めない。 |
| `vault_sealed` | 503 | 人間が UI で解封する必要があると伝える。保管庫のパスフレーズを**決して**求めない。 |
| `not_found` | 404 | `list_secrets` で確認し直す。参照を推測しない。 |
| `reason_required` | 400 | 具体的な理由を添えて繰り返す。プレースホルダーは使わない。 |
| `use_not_configured` | 400 | 人間にアイテムのバインドを依頼するか、本当に必要なら値を読む。 |
| `use_not_allowed` | 403 | 必要な URL を述べる。他の URL を探らない。 |
| `upstream_failed` | 502 | 一度だけ再試行し、その後報告する。自分でサービスを呼ぶためにシークレットを求めない。 |

## 7. 何かがおかしいとき

| エージェントの発言 | 意味 | 対処 |
| --- | --- | --- |
| 「unauthorized」 | トークンが認識されない | `BSC_TOKEN`、`--token-file`、URL を確認する |
| 「token_expired, renewable: false」 | 更新可能な期間を過ぎている | UI で新しいトークンを発行する |
| 「scope_mismatch」 | 保管庫は正しいが、トークンが違う | スコープを広げるか、そのパス用のトークンを発行する |
| 長時間の「approval_pending」 | 誰も承認していない | 受信箱を開く。次回はタスクセッションを検討する |
| 「vault_sealed」 | デーモンが再起動した | UI で解封する。エージェントがパスフレーズを知ることは決してあってはならない |
| シークレットの貼り付けを求めてくる | 指示を無視している | 拒否する。本当に `bsc mcp` を使っており、シェルツールを使っていないか確認する |

## 8. アンチパターン

- プロンプト、`CLAUDE.md`、コミットされた `.env`、または URL の中にある `bsct_…`
  トークン。トークンは認証情報です。認証情報として扱ってください。
- すべてのエージェントで共有される 1 つの広いトークン。台帳を読む価値あるものに
  しているのはスコープです。
- MCP が使えるのに、エージェントにシェルツールから API を `curl` させること。値が
  プロセス引数とシェル履歴に残ります。
- パイプラインを静かにさせるために、サービスアカウントの承認をオフにすること。
  代わりにタスクセッションを開くか、事前承認してください。どちらも自然に終了します。
- 実行を先に進めるために「今回だけ」シークレットを貼り付けること。それこそ、この
  システムが不要にするために作られた、まさにその出来事です。

# ユーザーガイド

**対象:** Bastet Secret Chain 0.2.0
**言語:** [繁體中文](../zh-Hant/guide.md) · [简体中文](../zh-Hans/guide.md) · [English](../en/guide.md) · **日本語** · [한국어](../ko/guide.md)
**関連:** [インストール](install.md) · [エージェントガイド](agents.md)

このガイドは、保管庫を所有する人のためのものです。認証情報を登録し、どのエージェント
が何を読めるかを決め、承認の問い合わせに答え、そして後から誰が何を読んだかを証明
するまでを扱います。

---

## 1. 概念を 1 つの表で

| 用語 | 意味 |
| --- | --- |
| **保管庫** | 暗号化された 1 つのファイル。*施錠済み*とは鍵がメモリ上になく、何も読めない状態です。あなた自身も読めません。*解封済み*とは、人間がパスフレーズを入力した状態です。 |
| **アイテム** | 1 つの認証情報。ログイン、API キー、サービスアカウントの JSON、SSH 鍵など。パス、名前、種別、タグを持ちます。 |
| **バージョン** | 変更のたびにバージョンが追加され、古いものも読める状態で残ります。ローテーションは上書きではなく、バージョンの追加です。 |
| **参照（`sref_…`）** | アイテムの安定したアドレス。例: `https://…/v1/secrets/sref_7Qn4…`。**それ自体は何の権限も与えません。** チケットや設定ファイルに貼っても安全です。 |
| **トークン（`bsct_…`）** | エージェントが認証に使うもの。スコープ付き、有効期限付き、失効可能、レート制限付きです。発行時に一度だけ表示されます。これは紛れもなく認証情報です。 |
| **スコープ** | トークンが到達できるパス接頭辞とタグ。`prod` は `prod/` 配下すべてを含みます。それ以外は一覧にすら現れません。 |
| **承認** | 価値の高いアイテムは、読み取りのたびに人間に確認します。エージェントは待機します。失敗するわけではありません。 |
| **事前承認/付与** | 一度承認すると、そのトークンはそのアイテムを、付与の有効期限が切れるまで確認なしで読めます。あらかじめ付与しておくこともできます。 |
| **タスクセッション** | エージェントに作業を渡す前に開いておく時間枠。その枠とスコープの中での読み取りは、あなたを中断させることなく記録されます。自動的に延長されることはありません。 |
| **監査チェーン** | 各レコードが直前のレコードのハッシュを含む、追記専用の台帳。どんな改変もチェーンを壊し、それが見えるようになります。 |

ここから 2 つのルールが導かれます。一度覚えておく価値があります。

- **参照 URL はシークレットではありません。トークンはシークレットです。** URL は
  シェル履歴、ログ、エージェントの記録に残ります。それで構いません。URL だけでは
  何も取り出せないからです。
- **あなたのパスフレーズは誰にも復旧できません。** メンテナーにも、管理者にも、
  AI アシスタントにもです。保管庫ファイルをバックアップしてください。

## 2. 最初の 5 分

1. <http://127.0.0.1:8787/>（またはお使いのサーバーのアドレス）を開き、パスフレーズ
   で**解封**します。パスフレーズはそのマシン上のデーモンにのみ渡り、他のどこにも
   送られません。
2. **New secret** を押します。`prod/gcp` のようなパスと `firebase-admin` のような
   名前を入力し、種別を選び、値を貼り付けます。あるいは認証情報のファイルをその
   フィールドに直接ドロップします。ディスクに届く前に暗号化されます。
3. **📋 Copy reference** を押します。これでどこにでも貼れる URL が手に入ります。
   それ自体は何も取り出しません。
4. **Agent tokens → Mint token** へ進みます。エージェント名を示すラベル、その
   エージェントの仕事に見合った最小限のパススコープ、作業期間を超えない有効期限を
   設定します。`bsct_…` の値は**一度だけ**表示されます。そのままエージェントの
   設定ファイルに入れてください。
5. エージェントに参照を渡して読ませます。その読み取りが **Audit chain** に現れる
   のを確認してください。

## 3. 画面構成

左から右へ、7 つのタブがあります。

### 🏠 Overview

アイテム数、30 日以内に期限が切れるもの、保留中の承認、アクティブなタスク
セッション、有効なトークン、そして監査チェーンの状態。バージョン行にはビルドが
表示されます（例: `0.2.0+f23d51a`）。アップグレード後にマシンの挙動がおかしいとき
に役立ちます。**Change passphrase** もここにあります。

### 🗂️ Secrets

パスのツリーと、種別・環境によるフィルタ付きの一覧です。検索は名前、パス、タグを
対象とします。ブラインドインデックス経由で動作するため、検索語が平文で保存される
ことはありません。`/` を押すと検索へジャンプします。

バッジは、そのアイテムの特別な点を示します。

| バッジ | 意味 |
| --- | --- |
| 🔴 | 読み取りのたびにあなたの承認が必要 |
| 🏠 | この UI でのみ承認可能 — 外部チャネルなし |
| 🔗 | *使用バインディング*を持つ: エージェントは値を見ずに使用できる |
| 🔄 | ローテーション期限超過 |

アイテムを開くと 4 つのタブが現れます。**Detail**（メタデータ、有効期限、
ローテーション間隔、削除）、**Versions**（履歴、新しいバージョンの追加）、
**Use binding**（セクション 7）、**Audit**（このアイテムに関するすべてのイベント）
です。

**Reveal** は値を数秒間表示し、その後隠します。承認が必要なアイテムでは、パス
フレーズをもう一度入力する必要があります。コピーするとクリップボードに入ります。
使い終わったらクリップボードをクリアしてください。

### 🎫 Agent tokens

発行、確認、失効を行います。各トークンはラベル、スコープ、有効期限、任意の読み取り
クォータ、そして 1 分あたりのレート制限を持ちます。一覧には、有効・期限切れ・失効
済みの状態と、クォータの残量が表示されます。**Revoke** は即座に効きます。

このタブにある **Pre-authorizations** パネルはセクション 5 で説明します。

### 🔔 Approvals

受信箱です。各エントリには、どのトークンがどのアイテムを求めているか、エージェント
が示した理由、リマインダーが何段階進んだか、そして自動拒否までのカウントダウンが
表示されます。`a` で承認、`d` で拒否です。承認すると同時に付与も発行されるため、
同じトークンは付与の有効期限が切れるまでそのアイテムについて再度尋ねません。

### ▶️ Task sessions

エージェントに作業を渡す前に時間枠を開きます。スコープと期間（15 分から 2 時間、
上限は 8 時間）を指定します。その枠内での読み取りは、確認なしで記録されます。枠が
自動的に延長されることはなく、終了すれば確認が復活します。

### ⏰ Expiry

アイテムとトークンを、期限切れが近い順に並べたものです。何かが壊れてからではなく、
壊れる前にローテーションするために使ってください。

### ⛓️ Audit chain

すべてのイベント: 解封、作成、読み取り、発行、失効、承認、削除、移行。
**Re-verify** はチェーン全体を再計算し、健全であるか、あるいはどのレコードで壊れた
かを報告します。チェーンにはアイテム ID、実行主体、理由が含まれます。値は決して
含まれません。

## 4. 日々の作業

**認証情報を追加する。** New secret → パス、名前、種別、タグ、値。任意で、有効期限、
日数単位のローテーション間隔、そして *Ask me before every read* を設定します。

**ローテーションする。** アイテムを開く → Versions → Add version。古いバージョンは
読める状態のまま残り、エージェントには新しいものが渡り、ローテーションの時計が
リセットされます。Detail タブで日数単位の間隔を設定すると、期限を過ぎたときに 🔄
バッジが表示されます。

**何に承認を要求するかを決める。** サービスアカウント、クラウドの root キー、署名
証明書はデフォルトで承認が必要です。ログインや通常の API キーは不要です。これは
アイテムごとに変更できます。確認が頻繁すぎると感じたら、それはタスクセッションか
事前承認を使うべきサインであって、承認をオフにするサインではありません。

**削除する。** Detail → Delete item、理由を添えて。暗号文、バージョン、インデックス
の行、付与が消えます。台帳には履歴が残ります: `item_deleted`、誰が、なぜ。取り消し
はできません。

**パスフレーズを変更する。** Overview → Change passphrase。すべてのデータ鍵が
1 つのトランザクションで再ラップされ、インデックスが再構築されます。古いパス
フレーズは使えなくなり、全員がログアウトされます。アイテムの値そのものは再暗号化
されないため、大きな保管庫でも高速です。

**施錠する。** **Lock** は保管庫を直ちに施錠します。鍵はメモリから消え、エージェント
には `vault_sealed` が返り、次の読み取りは人間を待ちます。共有マシンを離れるときは
これを実行してください。

## 5. エージェントにアクセスを与える

4 つのつまみがあります。上げる前に、まず下げてください。

| つまみ | 設定の指針 |
| --- | --- |
| **スコープ** | 仕事をカバーする最も狭いパス接頭辞。`prod` ではなく `prod/mobile`。 |
| **有効期限** | 作業期間より長くしない。アシスタントなら 1 日、パイプラインなら 1 時間。 |
| **読み取りクォータ** | 3 つのシークレットを読むパイプラインなら 3 に設定する。 |
| **レート制限** | デフォルトの毎分 60 は寛容です。機械向けにはもっと下げてください。 |

エージェントごと、プロジェクトごとに 1 つのトークンを。そうすれば、失効の代償は
1 エージェントの 1 プロジェクト分で済み、台帳はどのエージェントが何をしたかを語り
ます。

**更新。** トークンは、自身の有効期間の最後の 4 分の 1 の中でのみ（加えて 5 分の
猶予期間）自らを延長でき、ハードな上限を超えることは決してありません。更新が
スコープを広げることはありません。

**事前承認。** 実行中にエージェントが承認必須のアイテムを必要とすると分かっている
なら、あらかじめ付与しておきます: Agent tokens → Pre-authorize → トークン、
アイテム、期間。トークンの有効期限を上限とし、いつでも失効させられます。これが、
都合の悪いタイミングで尋ねられるのを避けつつ、そのアイテムを全員に対して弱めない
ためのやり方です。

## 6. 承認と、それに摩耗させられないために

承認必須のアイテムが読まれると、エージェントは「pending」を受け取って待機します。
あなたにはリマインダーの階段が届きます。

| 段階 | タイミング | 何が起きるか |
| --- | --- | --- |
| 1 | 即座 | デスクトップ通知 |
| 2 | 20 秒後 | 音付きで再通知 |
| 3 | 60 秒後 | 設定されていれば外部チャネル（Telegram） |
| — | 5 分後 | **自動的に拒否**され、記録されます |

各段階は台帳に書き込まれるため、時間に追われた状況で下した判断も、後から見える
ままです。

外部チャネルは送信専用です。メッセージはアイテムと理由を示しますが、値も、それを
取り出せるリンクも決して含みません。**ローカル承認のみ**と設定されたアイテムは
そこに通知されますが、承認できるのは UI だけです。

承認疲れは煩わしさではなくセキュリティ上の問題です。反射的に Approve を押す人は、
承認が一切ないよりも悪い状態です。尋ねられる回数が多すぎるなら、作業の期間だけ
**タスクセッション**を開くか、特定のアイテムとトークンを**事前承認**してください。
どちらも範囲が限られており、どちらも記録されます。承認を完全にオフにするのは、
最後の最後に手を伸ばす選択肢です。

## 7. エージェントに、値を見せずにシークレットを使わせる

常に 1 つのサービスにしか送られないアイテム、たとえばデプロイキーや Webhook の
トークンについては、値を渡す代わりに、そのサービスに紐づけることができます。

アイテムを開く → **Use binding** → 許可する URL パターン（`https://` のみ、接頭辞
には末尾に `*`）、`Authorization: Bearer {value}` のようなヘッダーテンプレート、
そして許可するメソッド。

その後エージェントは、URL とボディを添えて `use_secret` を呼びます。デーモンが
認証情報を差し込み、自らリクエストを送信し、サービスの応答を返します。値が
エージェント、記録、ログに入ることはありません。バインディングの範囲外のリクエスト
は拒否され、HTTPS でない URL や内部アドレスも同様に拒否されます。

通常の読み取りに戻すには、バインディングをクリアしてください。

## 8. 何が起きたかを証明し、データを取り出す

**チェーンを検証する。** Audit chain → Re-verify、または保管庫が施錠された状態で
オフラインで検証します。

```sh
bsc audit --vault ~/.bsc/vault.bsc
```

**アンカー。** 検証は何も*改変*されていないことを証明しますが、ファイルの所有者は
原理的には末尾のレコードを削除できます。アンカーは、チェーンの長さと先頭を保管庫の
外に記録します。

```sh
bsc audit --anchor-file ~/anchors/bsc.jsonl
```

そのファイルは、保管庫の所有者がひそかに書き換えられない場所に保管してください。
別のディスク、ログ転送先、git リポジトリなどです。サーバーでは、
[インストールマニュアル](install.md#46-台帳の日次アンカー推奨)のタイマーを使って
毎日実行してください。

**緊急時エクスポート。** すべてのアイテムとすべてのバージョンの完全なエクスポート
で、*別の*パスフレーズで封印されます。

```sh
bsc export --out ~/bsc-export-2026-09-04.bscx
bsc import --in ~/bsc-export-2026-09-04.bscx     # into another vault
```

保管庫のパスフレーズの再利用は拒否され、ファイルの上書きも拒否されます。バンドル
に平文は含まれません。トークン、セッション、承認、台帳は意図的にエクスポートされ
ません。インポートは同じ認証情報での新たな出発であって、認可状態の複製ではない
からです。

エクスポートは保管庫そのものと同じように扱ってください。暗号化し、マシンの外に置き、
決してリポジトリに入れないことです。

## 10. 続ける価値のある習慣

1. パスフレーズは自分で入力します。他の誰も、人間であれ AI であれ、それを必要と
   することは決してありません。
2. `bsct_…` トークンを決してチャットに貼り付けないこと。設定ファイルに入れるもの
   です。
3. 狭く短いトークンを発行し、作業が終わったら失効させること。
4. 保管庫ファイルをバックアップし、コピーをマシンの外に保管し、`bsc audit` が
   そのバックアップを読めることをテストすること。
5. 何も問題がないときにも、ときどき台帳を読むこと。正常な状態がどう見えるかは、
   そうやって身につきます。
